# Cursor: одно окно, сразу IDE

## Проверенный случай — 2026-11-07

На macOS с Cursor **3.29.9** при запуске появлялись десятки окон Agents;
на снимке macOS показывала около **29 ГБ** памяти у Cursor.
`window.restoreWindows: "one"` уже было установлено и проблему не решало.

Проверка установленного `out/main.js` показала отдельный путь запуска:
Cursor добавляет все временные рабочие пространства из `Workspaces/`
через `getUntitledWorkspaces()` независимо от обычной настройки восстановления.
На этом Mac их было **22**. Очистка одного списка `windowsState` не помогла:
при следующем запуске Cursor снова находил временные рабочие пространства.

Что реально помогло:

1. Отключить старт в Agents отдельными настройками Cursor.
2. Отключить восстановление прежних окон и использовать текущее окно для файлов/папок.
3. При полностью закрытом Cursor перенести служебную папку `Workspaces`
   в резервную копию и сбросить списки восстановления окон.
4. Запустить Cursor обычным способом. Проверено в интерфейсе: редактор IDE;
   в меню **Window** только одно окно **Cursor**.

Расход памяти после исправления не измерялся. Windows/Linux этим запуском
не проверены. Внутренние ключи ниже подтверждены для 3.29.9 и могут измениться.

## Настройки для всех компьютеров

Откройте палитру команд → **Preferences: Open User Settings (JSON)** и добавьте
поля из [`settings.json`](settings.json) к существующему объекту. Не заменяйте
весь свой файл: в нём могут быть темы, расширения и другие настройки.

`window.restoreWindows: "none"` означает чистый запуск IDE без прежних проектов.
`window.openFoldersInNewWindow` и `window.openFilesInNewWindow` со значением
`off` направляют открываемые файлы и папки в текущее окно. Явная команда
**New Window** по-прежнему может создать другое окно.
`files.hotExit: "onExitAndWindowClose"` сохраняет механизм резервирования
несохранённых редакторов, но не заставляет открывать все проекты с резервными
данными на старте. Это не команда сохранения файлов проекта на диск.

В настройках самого Cursor выберите восстановление последних окон вместо
старта в Agents. Название пункта зависит от версии. В 3.29.9 этому соответствуют
ключи в `User/globalStorage/state.vscdb`, таблица `ItemTable`:

- `cursor/userWindowRestorationPreference` = `lastUsedWindows`;
- `cursor/userOpenAgentsWindowOnStartupPreference` = `false` (строка).

Это **не поля settings.json**. Скрипт ниже выставляет их на macOS.

## Применить на другом Mac

Требуется Python 3. Сохраните работу и полностью завершите Cursor через **⌘Q**.
Если приложение зависло — используйте «Принудительно завершить» в macOS;
несохранённые изменения при принудительном завершении могут потеряться.
Скрипт сам процессы не завершает и откажется работать при запущенном Cursor.

Из корня клона `terminal-configs`:

```bash
# Только диагностика, без изменений
python3 cursor/fix-startup-macos.py

# Настроить запуск IDE; без переноса временных рабочих пространств
python3 cursor/fix-startup-macos.py --apply

# Если при запуске появляется множество окон — полный вариант исправления
python3 cursor/fix-startup-macos.py --apply --archive-workspaces
```

По умолчанию используется `~/Library/Application Support/Cursor`.
Скрипт поддерживает обычный JSON. Если `settings.json` содержит комментарии
или завершающие запятые (JSONC), он остановится **до изменений**. В таком случае
добавьте настройки вручную и приведите файл к корректному JSON перед запуском
скрипта; не стирайте остальные настройки.

Перед изменениями создаётся локальная папка `User/startup-backup-<дата-время>`:
настройки, согласованная копия SQLite через backup API, списки окон и, при
`--archive-workspaces`, вся папка временных рабочих пространств. Скрипт не удаляет
проекты, `Backups`, `workspaceStorage`, историю чатов и расширения.
Не загружайте эти резервные копии в Git: они содержат личные данные.

**Последствие переноса:** старые временные многопапочные рабочие пространства
перестают открываться автоматически; старые ссылки на них в Recent могут
перестать работать. Обычные папки проектов и сохранённые `.code-workspace`
открываются вручную через Open Project / Open Workspace from File.
Для возврата временной сессии используйте резервную копию, как описано ниже.

После запуска Cursor проверьте:

1. Открылась IDE с редактором / Open project, а не окно Agents.
2. В меню **Window** перечислено одно окно.
3. Завершите Cursor и откройте ещё раз обычным способом — результат сохраняется.

## Windows и Linux — перенос решения, требует проверки

Те же пользовательские настройки можно добавить через интерфейс. Данные
обычной установки находятся здесь:

- Windows: `%APPDATA%\Cursor` (в Windows, **не** в WSL).
- Linux: `${XDG_CONFIG_HOME:-~/.config}/Cursor`.
- macOS: `~/Library/Application Support/Cursor`.

На Windows/Linux автоматический скрипт не запускайте: он предназначен для macOS.
Если остаётся массовое открытие окон, полностью закройте Cursor, сделайте
резервную копию его данных и проверьте наличие временных `Workspaces/*/workspace.json`.
Принцип исправления тот же: перенести `Workspaces` в резервную папку вне
`Workspaces`, затем восстановить одно окно IDE. Внутренние ключи и списки
восстановления нужно сверить с установленной версией перед правкой; не переносите
чужую `state.vscdb` между компьютерами.

## Откат на том же компьютере

Закройте Cursor. Сначала сохраните текущее состояние в отдельную копию,
особенно если после исправления уже работали в новых окнах.

- Верните нужные настройки из сохранённого `settings.json`.
- Для отмены режима запуска достаточно вернуть прежние два ключа из копии
  `state.vscdb`; полная замена базы может откатить и другую работу после исправления.
- Для возврата временных рабочих пространств перенесите каталоги из резервной
  `Workspaces` обратно в служебную `Workspaces`, без перезаписи одноимённых каталогов.
  Это может снова вызвать массовое открытие окон.
- `storage.json` и `storage.json.vsctmp` содержат старые списки восстановления;
  возвращайте их только для полного возврата прежней сессии при закрытом Cursor.

Резервная копия — для исходного компьютера: в рабочих пространствах и списках
могут быть абсолютные пути. Для другого ПК применяйте настройки и процедуру,
а не копию личного состояния.
