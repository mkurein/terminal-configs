# Cursor: одно окно, сразу IDE

## Проверенный случай — 2026-11-07

На macOS с Cursor **3.29.9** при запуске появлялись десятки окон Agents;
на снимке macOS показывала около **29 ГБ** памяти у Cursor.
`window.restoreWindows: "one"` уже было установлено и проблему не решало.

Проверка установленного `out/main.js` показала отдельный путь запуска:
Cursor добавляет все временные рабочие пространства из `Workspaces/`
через `getUntitledWorkspaces()` независимо от обычной настройки восстановления.
На этом Mac их было **22**. Очистка одного списка `windowsState` не помогла:
при следующем запуске Cursor снова находил временные рабочие пространства.

Что реально помогло:

1. Отключить старт в Agents отдельными настройками Cursor.
2. Отключить восстановление прежних окон и использовать текущее окно для файлов/папок.
3. При полностью закрытом Cursor перенести служебную папку `Workspaces`
   в резервную копию и сбросить списки восстановления окон.
4. Запустить Cursor обычным способом. Проверено в интерфейсе: редактор IDE;
   в меню **Window** только одно окно **Cursor**.

Расход памяти после исправления не измерялся. Linux не проверялся.
Внутренние ключи ниже подтверждены для 3.29.9 (macOS) и 3.18.9 (Windows)
и могут измениться.

## Проверенный случай Windows — 2026-11-09

Windows 11, Cursor **3.18.9**, установка в `%LOCALAPPDATA%\Programs\cursor`.
При запуске открывались 3 окна Agents и окно IDE. В `settings.json` стояло
`window.restoreWindows: "one"`, режим запуска Cursor — `default`: в этой
версии `default` и `agentWindow` открывают Agents, IDE — только `lastUsedWindows`.

Исправление то же, что на macOS, но с первого раза не сработало по трём причинам:

1. **Запуск из встроенного терминала Cursor.** Процесс, запущенный из терминала
   Cursor (в том числе `Start-Process` и задача, созданная оттуда), Windows
   завершает вместе с Cursor — до применения настроек.
2. **`py -3` в PowerShell.** Профиль репозитория делает `py` алиасом
   `python.exe`, поэтому `Unknown option: -3`.
3. **Cursor открыли раньше, чем скрипт закончил.** `state.vscdb` весил
   **4,4 ГБ**; его резервная копия заняла около минуты. Cursor, открытый через
   ~8 секунд, прочитал старый список окон и записал его обратно: снова 3 окна
   Agents, хотя режим IDE уже применился.

Что сработало: запуск исправления **вне** Cursor, ожидание его полного
завершения и только после этого — запуск Cursor. После повторного сброса
`windowsState` / `backupWorkspaces` при закрытом Cursor открылось одно окно IDE.

## Настройки для всех компьютеров

Откройте палитру команд → **Preferences: Open User Settings (JSON)** и добавьте
поля из [`settings.json`](settings.json) к существующему объекту. Не заменяйте
весь свой файл: в нём могут быть темы, расширения и другие настройки.

`window.restoreWindows: "none"` означает чистый запуск IDE без прежних проектов.
`window.openFoldersInNewWindow` и `window.openFilesInNewWindow` со значением
`off` направляют открываемые файлы и папки в текущее окно. Явная команда
**New Window** по-прежнему может создать другое окно.
`files.hotExit: "onExitAndWindowClose"` сохраняет механизм резервирования
несохранённых редакторов, но не заставляет открывать все проекты с резервными
данными на старте. Это не команда сохранения файлов проекта на диск.

В настройках самого Cursor выберите восстановление последних окон вместо
старта в Agents. Название пункта зависит от версии. В 3.29.9 этому соответствуют
ключи в `User/globalStorage/state.vscdb`, таблица `ItemTable`:

- `cursor/userWindowRestorationPreference` = `lastUsedWindows`;
- `cursor/userOpenAgentsWindowOnStartupPreference` = `false` (строка).

Это **не поля settings.json**. Скрипты ниже выставляют их на macOS и Windows.

## Применить на другом Mac

Требуется Python 3. Сохраните работу и полностью завершите Cursor через **⌘Q**.
Если приложение зависло — используйте «Принудительно завершить» в macOS;
несохранённые изменения при принудительном завершении могут потеряться.
Скрипт сам процессы не завершает и откажется работать при запущенном Cursor.

Из корня клона `terminal-configs`:

```bash
# Только диагностика, без изменений
python3 cursor/fix-startup-macos.py

# Настроить запуск IDE; без переноса временных рабочих пространств
python3 cursor/fix-startup-macos.py --apply

# Если при запуске появляется множество окон — полный вариант исправления
python3 cursor/fix-startup-macos.py --apply --archive-workspaces
```

По умолчанию используется `~/Library/Application Support/Cursor`.
Скрипт поддерживает обычный JSON. Если `settings.json` содержит комментарии
или завершающие запятые (JSONC), он остановится **до изменений**. В таком случае
добавьте настройки вручную и приведите файл к корректному JSON перед запуском
скрипта; не стирайте остальные настройки.

Перед изменениями создаётся локальная папка `User/startup-backup-<дата-время>`:
настройки, согласованная копия SQLite через backup API, списки окон и, при
`--archive-workspaces`, вся папка временных рабочих пространств. Скрипт не удаляет
проекты, `Backups`, `workspaceStorage`, историю чатов и расширения.
Не загружайте эти резервные копии в Git: они содержат личные данные.

**Последствие переноса:** старые временные многопапочные рабочие пространства
перестают открываться автоматически; старые ссылки на них в Recent могут
перестать работать. Обычные папки проектов и сохранённые `.code-workspace`
открываются вручную через Open Project / Open Workspace from File.
Для возврата временной сессии используйте резервную копию, как описано ниже.

После запуска Cursor проверьте:

1. Открылась IDE с редактором / Open project, а не окно Agents.
2. В меню **Window** перечислено одно окно.
3. Завершите Cursor и откройте ещё раз обычным способом — результат сохраняется.

## Применить на Windows

Используйте [`fix-startup-windows.py`](fix-startup-windows.py) в **Windows
PowerShell или Terminal, не в WSL**. Требуется Python 3 с модулем SQLite
(входит в обычную установку Python). Запускайте от своего пользователя,
права администратора не нужны.

Порядок такой:

1. Сохраните работу.
2. Полностью завершите Cursor: все окна, не одно. Скрипт проверяет `Cursor.exe`
   через `tasklist.exe`, сам процессы не завершает и **откажется**, пока хотя бы
   один процесс жив. Ошибка проверки тоже считается «Cursor ещё запущен».
3. Запускайте исправление **снаружи Cursor**: двойной щелчок по BAT или
   Windows Terminal / PowerShell, открытые с рабочего стола. Встроенный терминал
   Cursor не подходит: пока он открыт, `Cursor.exe` есть, а после выхода из
   Cursor этот терминал закрывается вместе с ним и команда не доходит до конца.
4. **Не открывайте Cursor, пока скрипт не напишет «Настройки проверены»**
   (в BAT — `SUCCESS`). Скрипт копирует `state.vscdb`; при размере в гигабайты
   это занимает минуту и больше. Размер можно посмотреть заранее:
   `(Get-Item "$env:APPDATA\Cursor\User\globalStorage\state.vscdb").Length / 1GB`.
   Убедитесь, что на диске есть столько же свободного места.
5. Только после этого откройте Cursor обычным ярлыком.

Если Cursor всё же открыли раньше и окна Agents вернулись: снова полностью
закройте его и повторите `--apply --archive-workspaces`, дождавшись конца.
Повтор создаст ещё одну полную копию базы — старую лишнюю копию после проверки
можно удалить.

В PowerShell с профилем из `windows/powershell/` команда `py` — это алиас
`python.exe` (`Set-Alias -Name py -Value python`). У `python.exe` нет ключа
`-3`, поэтому `py -3 …` заканчивается `Unknown option: -3`. В PowerShell
вызывайте `python` без `-3`. Лаунчер `C:\Windows\py.exe -3` работает в **cmd**
(двойной щелчок по BAT, `cmd /c`), где алиас PowerShell не действует.

### Двойным щелчком

После обновления клона откройте папку `terminal-configs\cursor` в Проводнике
и дважды щёлкните **[`fix-startup-windows.bat`](fix-startup-windows.bat)**.
Сначала сохраните работу и полностью закройте Cursor.

BAT запускается через cmd, не через PowerShell, поэтому его `py -3` — это
`C:\Windows\py.exe`, а не алиас профиля. Дальше он ищет Python 3: сначала
`py -3`, затем `python`; проверяет наличие SQLite и запускает **полное
исправление** с `--apply --archive-workspaces`.
Перед изменениями Python-скрипт создаёт резервную копию. Старые временные
рабочие пространства будут перенесены туда и перестанут открываться автоматически.
Окно остаётся открытым как после успеха, так и после ошибки, чтобы прочитать
результат и путь резервной копии. При отсутствии Python выводится инструкция
по установке; автоматической установки, повышения прав и завершения Cursor нет.

Запуск не зависит от текущей папки; пути с пробелами поддерживаются.
Не переносите BAT отдельно: ему нужна вся папка `cursor` с Python-скриптами
и `settings.json`. Для диагностики или настройки без переноса сессии
используйте команды ниже. Сообщения BAT — на английском для совместимости
с Windows; вывод Python отображается в UTF-8.

### Из терминала

Только после полного выхода из Cursor, в отдельном окне PowerShell:

```powershell
cd C:\Project\terminal-configs
git pull --ff-only
python --version

# Диагностика без изменений
python cursor/fix-startup-windows.py

# Настройки IDE без переноса временной сессии
python cursor/fix-startup-windows.py --apply

# Полное исправление массового открытия окон
python cursor/fix-startup-windows.py --apply --archive-workspaces
```

`python --version` должен показать Python 3. Не подставляйте `py -3` в этот
PowerShell: профиль репозитория перехватывает `py`. Если PowerShell без этого
профиля и `Get-Command py` показывает `C:\Windows\py.exe`, тогда подходит
`py -3 cursor/fix-startup-windows.py`. Скрипт берёт данные из `%APPDATA%\Cursor`.
Portable-установки и нестандартный `--user-data-dir` этим скриптом не обслуживаются.
Не копируйте один файл отдельно: рядом нужны `cursor_startup.py` и `settings.json`.
Те же соседние файлы нужны и macOS-скрипту; используйте целую папку `cursor`.

Параметры, резервная копия, ограничения JSONC и последствия переноса совпадают
с macOS. UTF-8 с BOM поддерживается. База SQLite копируется через backup API,
включая данные из WAL; копирование одного файла базы вместо этого небезопасно.
`Workspaces` переносится только с явным `--archive-workspaces`. Если сессия
нужна для многопапочных проектов, сначала сохраните её как `.code-workspace`.

После применения откройте Cursor обычным ярлыком: должна открыться IDE,
в меню **Window / Switch Window** — одно окно. Закройте приложение полностью
и повторите запуск. Если ярлык явно содержит несколько проектов или
`--glass`, исправьте его отдельно: скрипт ярлыки не меняет.

**Статус проверки:** общая логика изменения настроек и резервирования,
проверка процессов Windows, отказ при работающем Cursor и ошибки входных
данных проверены автоматическими тестами на временных файлах. На Windows 11
с Cursor 3.18.9 (2026-11-09) `python cursor/fix-startup-windows.py --apply
--archive-workspaces`, запущенный вне Cursor после полного выхода, отработал;
после сброса списка окон при закрытом Cursor и его запуска открылось одно окно
IDE (проверено в интерфейсе). Двойной щелчок BAT отдельно не проверялся.

Проверить скрипты из корня репозитория (реальные настройки не изменяются):

```powershell
python -m unittest discover -s cursor/tests -v
```

## Linux — ручной перенос решения

Данные обычной установки: `${XDG_CONFIG_HOME:-~/.config}/Cursor`.
Автоматические скрипты предназначены для macOS и Windows. На Linux добавьте
пользовательские настройки через интерфейс. Перед переносом временных
`Workspaces/*/workspace.json` закройте Cursor и сделайте резервную копию.
Внутренние ключи и списки восстановления нужно сверить с установленной версией;
не переносите чужую `state.vscdb` между компьютерами.

## Откат на том же компьютере

Закройте Cursor. Сначала сохраните текущее состояние в отдельную копию,
особенно если после исправления уже работали в новых окнах.

- Верните нужные настройки из сохранённого `settings.json`.
- Для отмены режима запуска достаточно вернуть прежние два ключа из копии
  `state.vscdb`; полная замена базы может откатить и другую работу после исправления.
- Для возврата временных рабочих пространств перенесите каталоги из резервной
  `Workspaces` обратно в служебную `Workspaces`, без перезаписи одноимённых каталогов.
  Это может снова вызвать массовое открытие окон.
- `storage.json` и `storage.json.vsctmp` содержат старые списки восстановления;
  возвращайте их только для полного возврата прежней сессии при закрытом Cursor.

Резервная копия — для исходного компьютера: в рабочих пространствах и списках
могут быть абсолютные пути. Для другого ПК применяйте настройки и процедуру,
а не копию личного состояния.
